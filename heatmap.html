🔬 专病诊疗框架覆盖分析?

指标说明

框架疾病 Disease已建立临床路径的疾病数。全库疾病含未建路径的，与首页一致
就绪 Ready推荐≥5条且证据≥3条，可正式用于临床决策
测试中 Testing有推荐但未达到就绪标准，正在补充数据
未就绪 N/A无推荐陈述，诊疗框架尚未建立
推荐陈述 Rec.临床推荐条目总数（RecommendationStatement）
推荐动作 Action推荐关联的具体医嘱/操作数（recommends_action + blocks_action）
关联证据 Evidence推荐陈述直接关联的证据条目数，全库证据含未关联推荐的
关联指南 Guideline推荐陈述直接关联的指南数，全库指南含未关联推荐的
20维度覆盖 Dimension20个核心临床维度（17基础+3护理）的平均覆盖率，与首页/图谱探索一致（CORE_DIM_KEYS）

按 疾病 Disease → 临床路径 Pathway → 阶段 Stage → 规则 Rule → 推荐 Recommendation → 动作/证据/指南 Actions/Evidence/Guidelines 链路，分析每个疾病的专病诊疗框架就绪程度，同时展示20核心维度知识覆盖（与首页/图谱探索一致）。
🎯 瓶颈分析?

瓶颈分析说明

数据来源基于 CDSS 覆盖数据，统计每个链路层（路径/阶段/规则/推荐/动作/证据/指南）中有数据的疾病数量
断点含义某层有 0 条数据的疾病即为"断在该层"。例如某疾病有路径但没有阶段，则断在"阶段"层
优先级判断红色 = 超过 30% 疾病缺数据，需优先补齐；绿色 = 缺口≤10%，覆盖良好；黄色 = 介于两者之间
知识维度20 核心临床维度（与首页一致），反映疾病知识层而非决策链路的数据完整度
使用场景补数据时先看断点最多的层。例如"动作"缺得多，说明推荐有了但还没落地到具体医嘱
每一层有多少疾病断在这一层。断点越多的层，是优先补齐的方向。
📊 疾病覆盖明细?

疾病覆盖明细说明

20维度列与首页/图谱探索一致（CORE_DIM_KEYS），如 20/20 表示该疾病20个核心维度全部有数据
链路列路径 Pathway → 阶段 Stage → 规则 Rule → 推荐 Rec. → 动作 Action → 证据 Evidence → 指南 Guideline，数字为该疾病在此层的节点数
状态判定就绪 Ready = 推荐≥5且证据≥3；测试中 Testing = 有推荐但不达标；未就绪 N/A = 无推荐
